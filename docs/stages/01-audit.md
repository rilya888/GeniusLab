# Этап 1: Аудит и стратегия

[← К общему плану](../PLAN.md)

## Цель этапа

Зафиксировать текущее состояние трёх текущих сайтов и собрать требования для консолидации в единый сайт geniuslab.it.

## Входные данные

- Текущие сайты:
  - https://www.avatech.info/
  - https://www.assistenza-macbook.it/
  - https://www.apple-assistenza.it/
- Доступ к исходному коду (если есть)
- Финальный общий план `docs/PLAN.md`

## Задачи

1. **Аудит контента (3 сайта)**
   - Выявить дублирование текстов (например: «irreparabile, troppo costoso», «ripariamo direttamente le schede logiche»)
   - Найти ошибки (Spengilo → Spegnilo)
   - Проверить несоответствия (расписание: Lunedì–Sabato vs Sabato–Domenica chiuso)
   - Оценить полноту информации по услугам
   - Отметить конфликтующие формулировки и спорные claim'ы
   - Проверить медиа-активы (фото/графика/логотипы) для переноса
   - Зафиксировать: текущие медиа разрешены к использованию без ограничений

2. **Аудит технический**
   - Анализ HTML-структуры, семантика
   - CSS, JS, зависимости
   - Производительность (Lighthouse, Core Web Vitals)
   - Адаптивность под мобильные

3. **Аудит SEO**
   - Meta tags, Open Graph
   - Структура URL, sitemap
   - Индексация, внутренняя перелинковка
   - Риск keyword stuffing
   - Базовая оценка качества редиректопригодности URL (one-to-one потенциал)

4. **Инвентаризация доменов и структуры**
   - Составить список URL по 3 доменам (ключевые страницы)
   - Отметить страницы-кандидаты для one-to-one редиректов
   - Выделить уникальный контент каждого сайта
   - Выделить страницы приоритета `P1` (top 10 по трафику/лидам)
   - Источник для P1: Search Console + текущие лиды/звонки + финальная приоритизация owner

5. **Сбор требований**
   - Бренд: Genius Lab vs AvaTech — финальное позиционирование
   - Подтверждение канонического домена: geniuslab.it
   - Функциональность форм, отзывов, карты, WhatsApp CTA
   - Отзывы в v1: только Google Reviews (без ручного переноса текстовых отзывов)
   - Placeholder-данные: email форм, соцсети, реквизиты (до финального заполнения)

6. **Canonical contacts/hours (единый источник правды)**
   - Зафиксировать финальные телефоны, email, реквизиты, адрес(а), график работы
   - Источник данных: owner предоставляет в рамках аудита
   - Сверить единые значения для UI, schema.org и Google Business Profile

7. **Определение целевой аудитории и KPI**
   - Кто основной клиент (B2C, B2B, ритейлеры)
   - Метрики успеха (звонки, заявки, конверсии)
   - Baseline для KPI из общего плана: CWV (LCP/INP/CLS), органика, доля 404, качество one-to-one mapping

8. **Юридический pre-check контента**
   - Выявить формулировки с риском по бренду Apple (спорные claim'ы)
   - Подготовить список блоков для legal-ревизии на этапе 06

9. **UI/UX baseline под mobile-first и Liquid Glass**
   - Зафиксировать текущие проблемы мобильной версии на 3 сайтах
   - Зафиксировать визуальный шум/перегруженные блоки для устранения в этапе дизайна

## Результаты

- **Отчёт аудита** — документ с выводами по контенту, технике, SEO
- **Инвентаризация доменов** — таблица URL/приоритетов/направлений редиректов
- **P1 список URL** — top 10 критичных страниц для миграции и QA
- **Canonical contacts/hours** — единая таблица контактов и расписания
- **Документ требований** — функциональные и нефункциональные требования
- **KPI baseline sheet** — стартовые метрики для сравнения после запуска
- **Legal pre-check list** — спорные формулировки и зоны риска по контенту
- **Приоритизированный бэклог** — список задач для следующих этапов

## Связи с другими этапами

- **Архитектура** — опирается на выводы аудита (стек, структура страниц)
- **Дизайн** — использует требования и портрет аудитории
- **Контент и SEO** — бэклог содержит задачи по редактированию текстов
