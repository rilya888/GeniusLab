# Этап 8: Hypercare (постзапусковая стабилизация и оптимизация)

[← К общему плану](../PLAN.md)

## Цель этапа

Стабилизировать сайт после запуска на geniuslab.it, оперативно устранить дефекты и подтвердить достижение целевых KPI.

## Входные данные

- Сайт после cutover (этап 07)
- Runbook запуска и rollback
- Базовые KPI/метрики из этапа 01 и плана
- Migration QA sheet и P1 migration map
- Consent QA matrix и Legal sign-off pack
- Каналы оповещений (email + Telegram)

## Задачи

1. **Ежедневный мониторинг (первые 14–30 дней)**
   - Доступность, ошибки 404/500, SSL
   - Core Web Vitals (LCP, INP, CLS)
   - Отправка форм и доставляемость email
   - Проверка P1 страниц (top 10) как приоритетного контура

2. **SEO-мониторинг после миграции**
   - Проверка индексации новых URL
   - Контроль редиректов, canonical, sitemap
   - Отслеживание изменений в показах/кликах в Search Console
   - Контроль тренда 404 по old URL из migration QA sheet

3. **Проверка бизнес-событий**
   - Формы, клики по WhatsApp/телефону, контактные CTA
   - Корректность аналитики с учётом consent

3a. **Мониторинг trust/reputation блоков**
   - Проверка отображения и кликабельности блока Google Reviews
   - Отслеживание влияния trust-блоков на CTR и конверсию

4. **Обработка инцидентов**
   - Приоритизация: critical/high/medium
   - Фиксы и регресс-проверка
   - Применение rollback-процедуры при выполнении критериев отката
   - Owner on-call: подтверждённый получатель алертов (email + Telegram)
   - SLA реакции на critical: до 30 минут
   - DRI по эскалации и rollback decision: owner проекта

5. **Оптимизация и backlog**
   - Улучшения UX/контента по реальным данным поведения
   - Регламент обновления словарей и контента (чтобы не нарушать i18n-подход)
   - Формирование backlog v1.1 (SEO, производительность, контент)

6. **Операционный ритм hypercare**
   - Ежедневный статус-апдейт owner: incidents, forms, SEO, CWV, risk notes
   - Каналы отчётности: email + Telegram
   - Изменения в проде: только через согласованный change-log и приоритеты P1/P2
   - Шаблон daily-отчёта: incidents / forms delivery / SEO trend / CWV / actions / risks

## Результаты

- **Отчёт hypercare** — метрики, инциденты, принятые меры
- **Стабилизированный production** — без критичных дефектов
- **Backlog v1.1** — приоритизированные улучшения после релиза
- **Daily status log** — журнал ежедневных апдейтов и решений owner

## Связи с другими этапами

- Продолжает этап 07 и закрывает первый цикл релиза
- Даёт входные данные для следующей итерации развития сайта

## Критерии готовности

- [ ] В течение agreed-периода нет открытых critical-инцидентов
- [ ] Формы стабильно доставляют заявки на email
- [ ] SEO-миграция стабилизирована (без массовых ошибок редиректов/индексации)
- [ ] Trust-блоки (reviews/CTA) проверены и измеряются в аналитике
- [ ] SLA на critical-инциденты соблюдён
- [ ] Daily status log ведётся и завершён за период hypercare
- [ ] Сформирован и согласован backlog v1.1
