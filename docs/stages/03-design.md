# Этап 3: Дизайн-система и UX

[← К общему плану](../PLAN.md)

## Цель этапа

Создать дизайн-систему и макеты всех ключевых экранов для бренда Genius Lab.

## Дизайн-направление (обязательное)

- **Стиль:** Liquid Glass (в духе Apple UI): полупрозрачные панели, blur-слои, мягкие световые акценты
- **Палитра:** white/black/gray + прозрачные glass-слои (`alpha`)
- **Типографика:** SF Pro (основная гарнитура) + читаемая иерархия с высоким контрастом
- **Анимация:** плавная и функциональная, не блокирует взаимодействие
- **Доступность:** контрастность не ниже WCAG AA для ключевых сценариев

## Входные данные

- Документ архитектуры (этап 02)
- Sitemap, схема компонентов
- Документ требований, портрет аудитории (этап 01)
- P1 migration map (top 10 URL)
- Canonical contacts/hours (данные owner из аудита)
- Component interaction contract (CTA -> формы -> analytics -> consent)
- Референсы кнопок и control-patterns из библиотеки Xcode

## Задачи

1. **Дизайн-система**
   - Типографика (шрифты, размеры, иерархия)
   - Liquid Glass палитра и уровни прозрачности (surface tokens)
   - Компоненты: кнопки, карточки, формы, ссылки
   - Единый набор иконок: **Lucide** (единая толщина/стиль на всём сайте)
   - Кнопки: primary/secondary/ghost в стиле glass (по референсам Xcode, адаптировано под web)

2. **Wireframes и прототипы**
   - Низко- и среднедетализированные макеты
   - Потоки: главная → услуга → контакт, форма записи
   - Приоритетная проработка P1 страниц (top 10 URL) как первой волны

3. **Адаптивные макеты (mobile-first)**
   - Breakpoints: mobile (320-767), tablet (768-1023), desktop (1024+)
   - Проверка читаемости и удобства на малых экранах
   - Упрощённый visual mode для слабых устройств (меньше blur/эффектов)

4. **UI-компоненты**
   - Кнопки (primary, secondary, CTA)
   - Карточки услуг
   - Формы (контакт, запись)
   - Header, Footer, навигация
   - Состояния: default/hover/focus/active/disabled/error/success
   - Единые паттерны для CTA (call, WhatsApp, form submit) с местами под аналитические события
   - Form UX: один единый сценарий успешной отправки для всех форм

5. **Макет страницы Recensioni**
   - Блок для Google Reviews (виджет/embed)
   - Расположение, размеры, адаптивность
   - Только Google Reviews (без ручных текстовых отзывов)
   - Fallback-состояние на случай недоступности виджета (без кнопки перехода во внешний сервис)

6. **Стиль бренда Genius Lab**
   - Логотип, визуальный тон
   - Отличие от AvaTech (если требуется)
   - Подготовка зоны Footer под будущие реквизиты/контакты (placeholder layout)

7. **Анимация загрузки и появления контента**
   - Fade-in/slide-up (300-500ms), без визуального перегруза
   - Обязательная поддержка `prefers-reduced-motion`
   - Не маскировать загрузку скелетонами, если это ухудшает LCP
   - Ограничение: анимации только для `opacity/transform`, без тяжёлых сценариев
   - Отдельные правила для glass-эффектов: ограниченный blur, без постоянных expensive repaint

8. **Дизайн-контракты для следующих этапов**
   - Handoff для разработки: tokens, состояния компонентов, сетка, отступы, типографика, glass-token map
   - Handoff для SEO/контента: шаблоны блоков под metadata/schema и длинные сервисные тексты
   - Handoff для legal: расположение consent/ссылок на policy в формах

9. **Stress-test контента и состояний**
   - Проверка длинных/коротких заголовков и описаний на всех breakpoints
   - Макеты состояний: empty/loading/error для виджета отзывов и форм
   - Проверка переполнения для контактов/адресов/реквизитов

- **Гайд по компонентам** — описание, состояния, примеры
